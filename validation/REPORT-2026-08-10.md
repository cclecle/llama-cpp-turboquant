## 3. The one regression, and its fix

Upstream removed rocWMMA FlashAttention (`fa72aeccb`, #26046). On RDNA4 `amd_mfma_available()` is
false, so that was the **only matrix-core path for head size 256** - Qwen3.6-27B lost 24% of prefill.

**A cheap fix was tried and does not work.** Raising the dispatch cap from 128 to 256 aborts the
HSA queue: `fattn-mma-f16.cuh` prunes its own kernel body with `DKQ > 128 -> NO_DEVICE_CODE` under
`AMD_WMMA_AVAILABLE` (`AMD_MFMA_AVAILABLE` allows 256; RDNA does not). The DKQ=256 instance links
but has no device code for gfx1201. **Do not retry this** - recovering D=256 needs kernel work.

**rocWMMA was restored instead**, and it works:

| Qwen3.6-27B:HQ | prefill | decode |
|---|---|---|
| rocWMMA ON (restored) | 1841.9 | 125.9 |
| rocWMMA OFF | 1559.7 | 104.6 |
| production v4 | 1843.8 | 124.0 |

Parity with production. The runtime switch still behaves correctly on dense models - Devstral with
`rocwmma-fattn = off` is **+14.1% prefill / +8.3% decode** versus ON, and OFF on the rocWMMA build
matches a build with no rocWMMA at all (1849 vs 1837), so the switch reaches the same code path.

figures tuned on v4 were measured under non-deterministic speculation and may shift slightly.

## 6. Muse-Glimmer-30B (new architecture from this rebase)

Loads and generates. The speculation configuration in the ini was **wrong in two ways**:

- The commented `spec-type = draft-dspark` is the wrong type. The assistant is **DFlash**
  (`MuseGlimmerAssistantModel` -> `MODEL_ARCH.DFLASH`), and `--dspark` in the converter is
  hard-restricted to `DeepseekV4ForCausalLM`.
- It needs a **separate** drafter GGUF via `md =`; the target file has no draft tensors (52 blocks,
  0 of 731 tensors matching nextn/dflash/assistant).

Enabling `draft-dspark` **silently degrades to ngram-only** - measured, not inferred:

| variant | prefill | decode | accept | VRAM |
|---|---|---|---|---|
| none | 1494.4 | 21.7 | - | 26.4 |
| ngram-map-k4v | 1507.2 | 43.6 | 0.961 | 26.4 |
| draft-dspark + ngram | 1499.7 | **43.6** | **0.961** | 26.4 |
| **draft-dflash + ngram** | 1092.9 | **54.4** | 0.797 | 30.8 |

DFlash: **+24.6% decode over ngram, -27.5% prefill, +4.4 GiB.** Accepted as worthwhile given the
fleet's prompt caching. Held at `ub = 2048`.

## 7. NOT validated - what this report does not cover

- **34 of 41 configurations** were not swept (all `:VISION` variants, gemma family,
  Qwen3.6-27B-Fable family, AgentWorld, Qwen3-Coder-Next, Minecraft, Muse-Glimmer).
- **No concurrency soak.** `np > 1` under tensor split, repeated slot save/restore under load, and
  context-shift churn are untested on this build.
- **No vision/mmproj path tested** on any model.
- **Slot save/restore and checkpoint persistence** were not exercised beyond a round-trip in
  Tier 0; the EAGLE deferred-boundary restore was not re-verified on this build.
- Acceptance figures use synthetic filler context and are **indicative only** - EAGLE reading
  0.24-0.31 here versus 0.885 on real code is a property of the filler.
- Load times are **warm-cache** (`/proc/sys/vm/drop_caches` is read-only in this container).
